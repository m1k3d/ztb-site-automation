# Site diagrams

Diagrams use one wide landscape sheet (at least 1.8:1), with connectivity reading left to right: access switch → ZTB gateways → WAN providers → Zero Trust Exchange. The VLAN gateway table, WAN addressing, management/HA networks, and configuration notes sit underneath the topology. The preview fits the whole sheet; **Actual size** lets you inspect small details. Dense configurations use a larger landscape canvas and additional table columns, preserving every row. Visio exports explicitly select landscape A3 printing and fit to one page wide by one page tall. Use larger paper for dense sheets when printing at a readable scale.

For a saved diagram made with an older layout, choose **Download site diagram → Update diagram layout**. The button shows progress, then opens the updated diagram with its download options. This redraws PNG/SVG/VSDX from the saved snapshot without contacting the tenant or changing site configuration. It also adds PNG to older diagrams that previously had only vector exports.

The ZPA service card appears even when App Connector provisioning or application segment creation is not selected. It shows the service in the topology; it does not confirm provisioning or a live connection. Each VLAN’s IP app badge still reflects whether segment creation was requested and verified. Updating an older diagram’s layout also adds the ZPA card.

If site creation failed or its outcome is unknown, no deployed-site diagram is saved. You can still preview and download the planned diagram under **Branch settings → Diagram details**.

The bundled Exchange cloud is vector artwork from page 1 of the public [Zscaler Zero Trust Branch data sheet](https://www.zscaler.com/resources/data-sheets/zscaler-zero-trust-branch.pdf), © Zscaler, Inc. Appliance reference photos for ZT400, ZT600, ZT800, and ZT8010 come from page 4 of the same data sheet. A small photo appears in the title area, separately from the connected topology symbols. The template's `platform_type` selects the photo, including for custom or site-specific cloned templates. VM and unrecognized platforms do not get a guessed hardware photo. Older snapshots without a platform field may use an unambiguous model in the saved template name; custom names alone cannot identify hardware.

Gateway and switch symbols use flat, front-facing vector geometry with consistent outlines. The gateway includes the actual Zscaler wordmark; the generic switch uses compact switching arrows above a schematic Ethernet port bank. These are custom topology symbols, not vendor-supplied hardware stencils or a claim about physical port counts. They remain grouped and editable in VSDX. HA paths mirror each other above and below the switch centreline; enhanced HA's WAN Transit runs down the centre of the gateway pair. WAN links use a centred bundle of evenly spaced lanes, with a separate vertical path for every connection so one circuit cannot hide another. Interface labels are bold, and WAN addresses and VLAN gateway addresses use larger, darker text; status remains secondary.

The Zscaler wordmark comes from the public [Zero Trust Branch product page](https://www.zscaler.com/products-and-solutions/zero-trust-branch). The topology's appliance, switch, and ISP symbols are custom editable vector shapes, not an official Zscaler stencil pack. Source attributions are in `data/diagram_artwork.json`, `data/diagram_wordmark.json`, and `data/appliances/sources.json`. Rendering uses bundled assets and makes no external requests.

Every newly created site gets a configuration diagram automatically. On **Review rollout**, choose **View diagram** or **Download site diagram** beside the site result. Downloads include a **PNG preview**, a scalable **SVG image**, and an **editable Visio (.vsdx)** document. **All formats (.zip)** packages these three files for that site, with a short README explaining which format to open. **Saved deployment diagrams → Download all diagrams** packages every site in the selected run into one ZIP. Site names and numbered prefixes keep files distinguishable.

Under **Site details → Diagram details — optional**, you can name the downstream switch and each ISP. Give two WAN connections the same **Shared circuit** label only when they connect to the same ISP circuit. Without that label, each uplink has its own ISP symbol. These are documentation settings and never change tenant configuration. Branch copies and saved projects preserve them; CSV exports carry them in `diagram_options_json`.

In the same panel, **Upload customer logo** replaces the top-left Zscaler logo for this project's diagram previews and future deployments. JPG/JPEG and PNG files up to 2 MB are accepted. The image keeps its proportions within a 240 × 72 drawing-unit area, with extra header space above the site title; **Use Zscaler logo** restores the default. The setting is saved once per project and applies to every site in it. Gateway symbols, service cards, and the appliance photo keep their existing branding. Previously saved diagram snapshots keep the logo they were captured with, including when their layout is regenerated. Use **Update diagram layout** to apply the larger logo sizing to an existing saved diagram.

Logo processing stays local: the uploaded image is validated, stripped of metadata, resized, and embedded as a compact PNG in SVG, PNG, and VSDX exports. It is never uploaded to the tenant. Saved projects and exported rollout CSVs include this normalized image, so those files can carry customer branding between workspaces. CSVs with different logos must be imported into separate projects. Without a custom logo, the bundled Zscaler wordmark is always used.

Each circuit has a muted color shared by its physical connections, ISP cloud outline and label, and WAN table accent. Both HA peers use the same color when explicitly assigned to the same circuit; matching ISP names alone do not merge circuits. Colors identify circuits within the sheet, not priority, health, or which ISP carries ZIA/ZPA traffic. Circuit colors remain consistent when the same saved snapshot is redrawn or its WAN rows are reordered. Text labels and interface/IP details remain available without relying on color. Older saved diagrams gain the colors through **Update diagram layout**, without tenant calls.

Standalone sites with one connection per ISP use evenly spaced clouds centred around the gateway. Upper and lower WAN paths mirror each other, with aligned bend columns and equal horizontal runs; their opposite vertical segments remain separate. A single ISP connects straight across. HA and parallel connections retain separate lanes so their circuit colors stay visible.

**Preview site diagram** uses the current draft and already cached template information without contacting the tenant. It is labeled **Planned configuration** and can be downloaded as SVG or PNG. Load the selected template's interfaces to identify the hardware model, HA mode, HA port, and WAN Transit port. Preview does not deploy a site.

## What the diagram shows

- Site name, location, template, standalone/standard HA/enhanced HA mode, and capture time.
- One or two ZTB appliances, WAN circuits and addressing, Zero Trust Exchange, and requested ZIA/ZPA logical service connections.
- One trunk per LAN interface and a color-coded VLAN gateway legend: VLAN name, tag, zone, subnet, gateway address, interface, and status. A compact row beneath each VLAN shows **Routed tunnel**, **Segmentation**, and **IP app**; management VLANs include the same details in their network summary.
- Trunk links show every enabled VLAN assigned to that gateway port as a colored label, such as **VL10**, matching the VLAN table. Equal-width labels line up in columns, wrapping into additional rows without truncation. Standalone links fit up to five labels per row; HA links use narrower grids. Missing VLAN IDs show **ID ?**. Choose **Update diagram layout** to apply these labels and the Segmentation wording to an older saved diagram.
- Management and HA networks separately from client VLANs; UCaaS breakout when requested.
- One HA interface per gateway, inferred from the template's `ha` role, connected through the downstream switch.
- In enhanced HA, one WAN Transit link directly between the peers, using the template's `ha-data` interface on each gateway. Standard HA has no WAN Transit link. Missing or ambiguous roles are flagged instead of inventing interface assignments.

The switch, ISP circuit grouping, and physical cabling describe the intended design, not discovered wiring. Post-deployment read-back confirms the template's interface assignments against the site; differences are documented and site API values take precedence.

VLAN detail labels use the deployment draft for planned diagrams and the network read-back for saved deployment diagrams:

- **Routed tunnel: Yes / No** reflects `share_over_vpn`, the VLAN route-sharing flag. It does not mean a tunnel is established and is independent of ZPA segment creation.
- **Segmentation: On / Off (Lite)** reflects the supported VLAN DHCP modes (`inherit`/`on` versus `non_airgapped`). This describes the VLAN default, not individual asset exceptions or policy enforcement. **DHCP off** preserves that setting explicitly instead of claiming isolation is off. Zscaler documents the [VLAN-level Airgap-Lite setting](https://help.zscaler.com/zero-trust-branch/configuring-protection-mode-assets); a prefilled Airgap+ mask alone is not proof of Airgap+ mode.
- **IP app: Planned** means selected for creation. **Created (disabled)** requires the successful, verified ZPA staging report and confirmed network addressing fully covered by its IP destinations. The segment name appears once in the notes. **Not selected** means this rollout did not request creation, not that the tenant has no other segment. Failed or uncertain staging is **Unverified**; a confirmed prerequisite failure is **Not created**.

These annotations require no additional tenant calls. Missing/unverified network fields and older snapshots that did not capture these details show **Unknown**. Updating an older diagram's layout cannot recover settings absent from its saved snapshot. Diagram snapshot schema version 2 stores the new per-network information; version 1 snapshots remain renderable.

Solid lines show intended physical links. Separate blue ZIA and teal ZPA dashed paths leave the top and bottom of each ZTB gateway, away from physical WAN attachment points, and terminate directly at prominent service cards beside the Exchange. ZIA shows a globe with **Zscaler Internet Access / Internet & SaaS**; ZPA shows an application grid with **Zscaler Private Access / Private Applications**. Service cards show no status labels; the sheet heading and configuration notes carry verification context. The drawing does not label these paths as VPNs or assign a protocol or active ISP. Small gaps distinguish remaining line crossings from junctions. SVG, PNG, and VSDX use the same routing and gaps; a Visio service path remains one connector attached to its gateway and service card.

The diagram uses read-only API calls after configuration completes. Confirmed network values replace the submitted values, with notes for mismatches. Missing or inaccessible data remains visibly **unverified**. Failed deployment stages and pending management bindings appear in the notes. DHCP addresses are shown only if returned by the API. No tunnel-health or live-traffic test is performed; configured service connections are not a claim that tunnels are online.

Diagram capture/rendering failure does not fail or retry a tenant deployment. If a snapshot was saved but an export failed, **Regenerate diagram** rebuilds the files from that snapshot without tenant calls. Old snapshots never change when you edit the draft. A site that was not created by the run does not receive a new deployment diagram.

## Files and compatibility

Native files live under `out/runs/diagrams/<run>/`; Docker uses `/data/runs/diagrams/<run>/` in the existing persistent volume. CLI deployment also saves PNG/SVG/VSDX files beside its report. Application restarts preserve downloads but do not resume interrupted deployments. Runs made before this feature do not have snapshots and are not backfilled automatically.

PNG is generated locally from the same SVG using resvg, with bundled Liberation Sans fonts (regular and bold, SIL Open Font License in `data/fonts/LICENSE.txt`). It has a white background and is at most 4096 pixels wide, preserving the sheet's aspect ratio. Use the vector formats for dense sites and large-format printing. No browser, tenant credentials, external rendering service, or network connection is required to generate an export.

SVG is a self-contained vector drawing with the small appliance photo and optional customer logo embedded, and no remote assets or scripts. VSDX contains grouped vector devices, editable labels, connector relationships, and separate embedded images for the reference photo and optional logo. Visio, Miro, and Lucidchart support VSDX, but import fidelity and editing entitlements depend on the application. Miro imports SVG as a single image; use VSDX to edit devices and links. Very large SVG canvases may exceed an application's image-size limits.

The renderer was exercised with standalone, both HA modes, multiple WANs, and a 40-VLAN legend. VSDX examples were independently opened and rendered by LibreOffice. Native Microsoft Visio, Miro, and Lucidchart import/movement checks remain to be performed in those applications; XML validity or LibreOffice rendering alone does not establish their full editability behavior.

HA diagrams and CLI output do not enable HA UI deployment. The existing deployment gate remains in place.
