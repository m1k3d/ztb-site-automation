How to use

Prepare branches from a reference configuration, review the plan, then follow each deployment result.

  1. Choose a reference site

    Start with a working configuration. Check the template, gateway setup, networks, and optional services before using it for new branches.

  2. Prepare your branches

    Give each branch a unique site name and fill in its location, country, and network settings. Open a branch to resolve missing information, such as a WAN IP address.

  3. Select what to deploy

    Choose one branch for a pilot or select several for a rollout. Group selection includes ready branches with no recorded completion or existing-site result. HA branches can be exported as CSV; deployment from this workspace remains blocked. “Group by country” uses each branch’s Country field; a country checkbox selects its eligible branches. Grouping does not change deployment order.

  4. Review the destination and changes

    Choose “Review selected branches”, then “Preview deployment” and check the destination tenant, site names, and planned resources. Resolve any tenant-check errors before approving deployment. Selected branches run one at a time.

  5. Check the results

    Review the result and report for each branch. After successful configuration, verify appliance activation and connectivity. If a branch fails or only partly completes, inspect the tenant and failed stage before retrying.

What do the statuses mean?
Ready
The branch details are ready for preview. This does not mean deployment has succeeded or that tenant checks have passed.
Needs changes
Open the branch and resolve the highlighted fields before selecting it.
Completed
A successful deployment is recorded for this project and connected tenant. This is not a live health check. “No recorded result” does not mean the site is absent; tenant preview checks for existing sites, including sites created elsewhere.
Failed or incomplete
Review the report. Some resources may already exist, even if the overall deployment did not finish.
Existing site / skipped
The requested site was not created because a matching site was found. Check whether it is the intended branch or a naming conflict.
What if the site already exists?

The tool checks tenant site inventory for a matching name, ignoring capitalization and surrounding spaces. A matching existing site blocks creation; this is not an update or overwrite workflow.

If the complete inventory cannot be verified, creation is blocked. Resolve the lookup error before retrying. Avoid deploying the same site from two sessions at once.

What should I do after an error?

Read the branch report and identify the failed stage. Check the destination tenant for any site or template already created. A partial result may need recovery rather than a fresh deployment; do not rename a branch just to bypass an existing-site check.

If a template was created but site creation failed, verify that template and the site inventory before reusing it. Keep the report for troubleshooting.

Saving and returning later

Wait for “Saved on this computer” before closing the tab. Projects retain branch details, selections, country grouping, and your last view. Connections and approvals are not saved; reconnect and preview again after restarting the app.

Recorded results from deployments made with this version are shown for the same project and connected tenant. Earlier runs and deployments from other tools may have no recorded result here. Existing-site checks still run before creation.

Keep the local app running during deployment. There is no automatic retry or rollback. Download the report and inspect the tenant before recovering an interrupted run.
